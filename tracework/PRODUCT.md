# Tracework

A local, single-operator solution-engineering workbench. It turns immutable source evidence into reviewed proposals, accepted versioned meaning, architecture decisions, and independently usable engineering outputs.

Audience: solution engineers, architects, analysts, and developers working at a desk across multiple saved projects. Main success: trace any accepted claim or generated output back to its evidence, and deliberately decide what changes.

Five modes: Discover, Model, Design, Generate, Validate. Evidence, review, and durable run history remain accessible throughout. Synthetic example work is visibly labelled. External inference requires an API key and explicit data policy. Accepted state is always human governed.

Visual direction: a working technical review desk: warm paper, deep ink navigation, compact editorial tables, muted mineral green for accepted state, amber for unresolved review. No marketing dashboard. The evidence-to-proposal-to-model relationship is the first viewport's core mechanism. Desktop supports a persistent inspector; narrow screens put the same actions into a linear reading order.
